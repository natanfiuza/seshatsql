## Summary

Delivers the connection profile management experience (T04): users can now create, edit and delete database connection profiles from a dedicated dialog reachable from both the Tools menu and the toolbar, with validation, duplicate-name protection and a password workflow that never exposes secrets to the renderer.

To support the richer form, the persisted `connections.yml` document moves to schema **v2** (`environment` becomes a closed set plus an optional custom label, `color` is restricted to a fixed palette, ids are generated by the main process). Existing v1 files are migrated in memory on load, the original is preserved as `.bak`, and malformed files are quarantined instead of silently discarded — so no user input or ciphertext is lost during the upgrade.

## Technical Changes

- **Domain/persistence**
  - New `CONNECTION_ENVIRONMENTS`, `ConnectionsV2`, `ConnectionsV1` (legacy) and `PublicConnection.environmentLabel` types; `CONNECTIONS_SCHEMA_VERSION = 2`.
  - New `connection-palette.ts` with 8 canonical `#rrggbb` colors, `DEFAULT_CONNECTION_COLOR` and `isConnectionColor` guard.
  - New `connections-migration.ts`: tolerant v1 schema, environment alias mapping (`dev`/`desenvolvimento`/`homologacao`/`producao`…), unknown values preserved as `custom` labels, invalid colors replaced by the default, corrupt documents throw to trigger quarantine.
  - `parseVersioned` now takes an explicit `currentVersion` so preferences/tabs (v1) and connections (v2) version detection are independent.
- **Application**
  - `ConnectionsService.save` accepts an optional `id` (generated via injectable `newId`, default `crypto.randomUUID`), trims text fields, rejects blank required fields, rejects edits of unknown ids (`not-found`) and case-insensitive duplicate names (`duplicate-name`), and drops `environmentLabel` for non-custom environments.
  - `connectionInputSchema` is tightened: optional `id`, trimmed strings with min lengths, `z.enum` for color and environment, and `superRefine` enforcing `environmentLabel` only (and mandatorily) for `custom`.
  - Persistence runtime wires the v1→v2 migration into the YAML store.
- **Renderer**
  - New reusable `AppDialog.vue` with `role="dialog"`, `aria-modal`, focus trap (Tab/Shift+Tab), Escape → `request-close`, external focus guard and focus restoration.
  - New `ConnectionsDialog.vue` (list + detail), `ConnectionForm.vue` (inline validation, dirty tracking, password keep/remove semantics), plus `presentation.ts` and `validation.ts` helpers.
  - Shell plumbing: `ShellAction` union, `enabled`/`action` on menu items, `activate` events from `AppMenuBar` and `AppToolbar`, `Tools → Connections…` and a toolbar entry (`data-testid="connections-trigger"`).
  - i18n keys for all new strings across `en-US`, `es`, `fr`, `pt-BR`, `pt-PT` and the `Messages` type.
- **Tests**
  - New unit tests for palette, IPC contract, migration, form validation/presentation; new component tests for `AppDialog`, `ConnectionForm`, `ConnectionsDialog` and shell menu/toolbar wiring; new E2E suite `t04-connections.spec.ts` covering create/edit/delete, duplicate names, password preservation/removal, migration, corruption, future version refusal and inline validation; `s06-persistence` updated to the v2 file shape and generated ids.
- **Docs**: requirements, backlog, dependency/version notes, ADR 0016/0017 and T04 survey/spike/plan reports updated.

## Impact/Warnings

- **Data format (breaking for the file, handled automatically):** `connections.yml` is now `schemaVersion: 2`. Older clients cannot read it; v1 files are migrated on first load with the original copied to `connections.yml.bak`. Invalid v1 documents are quarantined (`.corrupt-*`), not deleted.
- **IPC contract change:** `connections.save` no longer requires `id` for creation (id is generated in the main process) and now rejects free-form `environment`/`color` values and `environmentLabel` outside `custom`. Any external caller relying on the old shape must be updated.
- **Behavior change:** duplicate names (case-insensitive, trimmed) are rejected; editing a non-existent id returns `not-found` instead of creating a second profile; empty `user` is no longer accepted by the write path (legacy records with empty user still load).
- **Security:** passwords remain DPAPI-encrypted and never leave the main process; the renderer only receives `hasPassword`. Editing without touching the password preserves the exact ciphertext byte for byte.
- **No new dependencies or environment variables.** Read-only mode is enforced when the file was written by a newer version, is unreadable or exceeds the size limit.
- **UX:** previously inert menu entries and toolbar buttons remain disabled; only `Tools → Connections…` and the connections toolbar button are active in this stage.
